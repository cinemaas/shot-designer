# Putting the cloud up

Three commands. Two of them need you, because they involve signing in — I can't
do that part.

### 1. Sign wrangler into Cloudflare  *(you)*

```bash
wrangler login
```

Opens a browser, you approve, done. A free Workers account is enough — SQLite
Durable Objects, which is what the live rooms and history run on, are on the
free plan.

### 2. Deploy

```bash
cd ~/ClaudeCodes/msc/shot-designer/cloud && ./build.sh && wrangler deploy
```

It prints the address, something like
`https://shot-designer.<your-subdomain>.workers.dev`.

### 3. Set the passphrase  *(you)*

```bash
wrangler secret put SYNC_KEY
```

Type any passphrase. This is the whole auth system: every device of yours enters
it once. Nobody needs an account, and share links don't need it at all.

Then in the app: **☰ → Cloud… → Connect to Cloud…**, paste the address and the
passphrase, and give yourself a name — that's what the director sees when you're
both in a scene.

## Trying it before you deploy

```bash
cd ~/ClaudeCodes/msc/shot-designer/cloud && ./build.sh && wrangler dev --port 8770
```

Runs the whole thing locally with no account at all. `.dev.vars` holds the dev
passphrase (`devkey`).

## After a code change

```bash
cd ~/ClaudeCodes/msc/shot-designer/cloud && ./build.sh && wrangler deploy
```

`build.sh` stages the app files the Worker serves. Skipping it deploys the old
front end.

## What runs where

| | |
|---|---|
| `src/worker.js` | Routing, passphrase check, signed WebSocket tickets, share links |
| `src/room.js` | One Durable Object per scene: versions, and the live room |
| `public/` | Generated by `build.sh` — the app itself, served from the edge |

Each scene is its own Durable Object, keyed by a hash of its path, so the
laptop, the iPad and a share link all land in the same room. History keeps the
last 60 saves per scene.

## Notes on the security of it

- One shared passphrase, compared in constant time, over HTTPS.
- WebSockets can't carry an auth header, so an authed call mints a ticket
  signed with HMAC-SHA256 that expires in 60 seconds; the socket presents that.
- Share links are unguessable ids and are enforced read-only *on the server* —
  a viewer's edit messages are dropped, not just hidden in the UI.
- Anyone with the link can watch the scene. Treat a share link like the scene
  itself: fine for a director, don't post it publicly.
